# Лимиты и тарифы

Три сферы трат — `App\Enums\UsageScope`:

| Сфера | Что считается | Как ограничено |
|---|---|---|
| `text` | Ответы моделей в чате и фоновые вызовы сервисной модели (названия, подбор картриджей, диффы) | Деньги в окнах: сессия + неделя |
| `agent` | Агентная и фоновая работа, голосовой ассистент | Деньги в окнах: сессия + неделя (свой бюджет) |
| `content` | Генерация картинок, видео, аудио | Баланс токенов |

Внутри всё считается в рублях — так сводятся к реальной себестоимости все провайдеры, без наценки.
Пользователь видит **энергию** (⚡): `энергия = рубли × config('limits.energy_per_rub')`, рубли — при наведении.

## Тариф (`plans`)

- `text_monthly`, `agent_monthly` — ₽ в месяц; `content_tokens_monthly` — токенов в месяц. `null` — без ограничений.
- Неделя = месяц ÷ 4,345 (`limits.weeks_per_month`).
- Сессия = неделя ÷ `sessions_per_week` — настраивается в каждом тарифе: 4,5 — сессия «маленькая», её можно
  выжечь 4,5 раза в неделю; 1,5 — сессия заметная.
- `session_hours` — длина сессии (6 ч).
- Тарифы: **Promo** — по умолчанию для всех, **Custom** — для калибровки (админы), чтобы правки не задевали
  остальных. Править можно любой — в админке, раздел «Тарифы».

## Окна — как у Claude

- Сессия начинается с первого запроса, когда предыдущая закончилась, и длится `session_hours`. Неделя — так же, 7 дней.
- `usage_windows` хранит открытые окна с накопленной суммой `spent` — проверка перед запросом читает две строки
  по индексу, без SUM: путь к первому токену не удлиняется.
- Лимит мягкий: пока `spent < лимит`, запрос проходит. Стоимость известна только после ответа, поэтому
  последний запрос может немного перебрать (мульти-запрос — по трате на каждую модель).
- Исчерпан — 429 с временем сброса; фронт знает заполнение заранее и блокирует отправку сам.

## Журнал (`usage_entries`)

- Каждая трата — строка: юзер, сфера, сумма в ₽ (по курсу на дату траты), источник (сообщение, фоновый вызов…).
- Пишется вместе с увеличением `spent` у окон, в одной транзакции. Источник правды для аудита и сверки.
- Стоимость неизвестна (нет расценок и провайдер не сообщил) — трата оценивается по токенам и самой дорогой
  известной цене вендора, помечается `estimated`: иначе через такую модель лимит обходился бы.
- Удалённые сообщения трату не возвращают.

## Токены контента

- Баланс — `users.content_tokens`, история — `token_transactions` (начисление по тарифу, админом, покупка,
  генерация, возврат; остаток после каждой операции).
- Ежемесячное начисление по тарифу — раз в месяц от предыдущего (`limits:grant-tokens`, ежедневно).
  Неиспользованные копятся.
- Админ начисляет токены любому пользователю, в том числе себе (раздел «Пользователи»).
- Списание — атомарно, условием «хватает ли баланса», при старте генерации; не удалась — возврат.
  Подключается вместе с генерацией контента.
