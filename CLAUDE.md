# AVAILIA

Интерфейс общения с нейросетями (аналог syntx.ai) через proxyapi.ru.

- `src/` — Laravel 13 (PHP 8.5) + Inertia v3 + Vue 3 + Tailwind 4: вся бизнес-логика, контроллеры, авторизация, биллинг, очереди.
- `gateway/` — Go 1.27: только стриминг ответов нейросетей (SSE/WebSocket), снаружи доступен через nginx по `/gw/`.
- Postgres 18, Redis 8. Всё крутится в докере (`docker-compose.yml`), управление — `./project.sh`.
- PHP, Composer и Node на хост не ставятся — только через контейнеры (`./project.sh artisan|composer|npm …`).

## Команды

| Команда | Описание |
|---------|----------|
| `./project.sh up` / `down` | Поднять / остановить стек |
| `./project.sh install` | Первичная установка (зависимости, миграции, справочники, курсы, суперюзер) |
| `./project.sh test` | Запустить PHPUnit тесты |
| `./project.sh artisan <cmd>` | Выполнить artisan команду |
| `./project.sh go <cmd>` | Выполнить go команду в контейнере gateway |

## Правила разработки

- **При добавлении нового функционала** — сразу писать тесты. Тесты — часть задачи, не опция.
- **Тесты — адекватная нагрузка (Not-overridable, общее правило при выполнении задач).**
Тесты — часть задачи, но их объём должен быть адекватным и предсказуемым; НЕ
«спамить» PR однотипными тестами и НЕ плодить их бесконтрольно, ориентироваться на производительность тестов.
- **Подход к тестам** — градированные тесты: высокая скорость прогона без потери
надёжности. Пометки-атрибуты открывают быструю навигацию по тестам, селекцию в CI
(запуск по категории или tier) и управление набором: что обязательно, что
дорого, что первым идёт под чистку.
- **Градация тестов** — каждый тестовый метод помечается группой <Категория><Tier>
(только на методе, не на классе), например D1, U2, A3.
- **Категория** — что тесту нужно для запуска; определяется базовым классом и
трейтами, одна на весь класс. Выбирай самую лёгкую из достаточных:
- U — чистая логика без Laravel (PHPUnit\Framework\TestCase);
- A — нужен Laravel (контейнер, конфиг, фасады), но без БД (Tests\TestCase);
- D — работает с БД (RefreshDatabase).
- **Tier** — насколько важен проверяемый функционал:
- 1 — ядро: критический функционал и бизнес-логика, на которых держится
работа приложения (безопасность и авторизация, платежи, цены и списания, лимиты тарифов,
интеграции с proxyapi и источниками курсов, регрессии ключевого функционала). 1–2 теста на кейс, обязательны. Добавляй TestDox — одну фразу по-русски, что именно
гарантирует тест: из этих фраз собирается читаемый список ядра.
- 2 — обычный функционал: 0–1 тест.
- 3 — косметика и отображение (элемент на странице, подписи, мета-теги):
0–1 тест; при чистке тестов в первую
очередь подвергается рефактору или слиянию с Tier2.
- Примеры: D1 — стоимость ответа переводится в валюту по курсу на дату сообщения;
U2 — разбор XML-ответа ЦБ; A2 — сервис собирает параметры из конфига;
D3 — название тарифа отображается в профиле.
- **Маркировка** — только стандартные атрибуты PHPUnit, свои теги не придумывать.
PHPUnit 12 читает только атрибуты — docblock-аннотации (@group, @testdox, @dataProvider) молча игнорируются:
- градация — #[Group('<Категория><Tier>')];
- суть ядра — #[TestDox('...')];
- однотипные кейсы — один тест с #[DataProvider('...')];
- тронул тест-файл — размечай его целиком.
- **Оправданная инфраструктура** — тест подключает только то, без чего не может
проверить поведение: Tests\TestCase — если нужен Laravel, RefreshDatabase —
если тест реально читает/пишет БД; тесты без БД не держи в классе с
RefreshDatabase, выноси в отдельный. Вместо #[RunInSeparateProcess] и Mockery
overload:/alias: внедряй зависимость через конструктор/DI и подменяй её
моком; без этого не обойтись — только с обоснованием в докблоке.
- При выполнении задачи убирай и объединяй старые избыточные тесты в
затронутой области: однотипные кейсы — параметризуй/совмести, дубликаты —
удали. Набор тестов не должен расти лавинообразно.
- Не теряй эффективность тестирования: не удаляй единственный тест на
поведение и тесты критичных сценариев; сокращение не скрывает реальные баги.
- Планка при ревью: размазанные, раздутые или лишние тесты в PR, а также
отсутствующая или неверная градация/маркировка — замечание уровня MEDIUM,
блокирующее мерж до исправления.
- **Если тесты не прошли** — не предлагать принимать решение со сломанными тестами. Сначала исправить тесты, потом двигаться дальше.
